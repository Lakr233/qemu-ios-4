# iPhone machine-model invariants

- Give every large artifact under `/private/tmp` an explicit owner and lifetime. Remove failed or disposable run directories immediately after extracting the required evidence, perform a post-run cleanup, and never accumulate multiple full NAND images without a checked free-space budget and an explicit reason to retain each one.
- Model the S5L8900 reset VROM as an alias of the single physical boot-ROM region. Disable that alias at the SYSIC VROM power transition so RAM becomes visible at address zero; never represent the transition with duplicate ROM or RAM contents.
- On current upstream QEMU, give migration-registered RAM/ROM either a `DeviceState` owner or no owner; a `MachineState` may own aliases and MMIO regions but is not a valid RAM/ROM migration owner.
- Do not substitute QEMU's PL190 model for the S5L8900 PL192: the consumed contract includes part ID `0x192`, 32 vector/priority slots, `VICSWPRIORITYMASK` at `0x24`, and acknowledge/complete through `VICADDRESS` at `0xf00`.
- Chain S5L8900 VIC1 into VIC0 instead of OR-ing their CPU outputs: XNU acknowledges only VIC0, expects the downstream vector to propagate through its `VICADDRESS`, and completes a VIC1 interrupt child-to-root.
- When MTTCG lets independent device producers update one daisy-chained VIC, serialize the complete chain's input level, priority/acknowledge state, and CPU output publication under one shared lock. Protecting only each controller or atomically changing one input bit still permits a stale cross-controller recomputation to leave an owner-cleared interrupt asserted. Keep single-threaded TCG on its already serialized lock-free path so a correctness guard for an experimental mode does not tax every interrupt in the stable mode.
- Anchor the S5L8900 RTC counter to its consumed 12 MHz timebase. Keep per-timer divider/source behavior conservative until a live producer/consumer pair proves it; OpeniBoot's event timer requires a 120,000-count interval to produce 100 Hz.
- Accept a USB-over-IP adapter only after the pinned `pymobiledevice3.irecv.IRecv` object has enumerated through a real loopback socket and exercised configuration; parser-only tests do not prove the runtime monkeypatch or PyUSB-shaped interface.
- For deterministic early-Guest debugging, hold the loaded kernel before its boot command, attach and arm raw-address breakpoints while the CPU is stopped, then release the boot command; attaching after handoff races fast driver startup.
- Preserve the timer mode encoded by configuration bit 4: 8C148 uses mode 2 (configuration `0x1150`) for rearmed one-shot deadlines, while OpeniBoot's mode 0 (`0x7040`) event timer auto-reloads. Treating both as periodic turns a minimum deadline into an interrupt storm.
- Keep a development NAND persistent across ordinary prepare and boot targets; expose full erasure as a separate explicit target so a restart cannot silently destroy a completed format or restore.
- When detaching the minimal GDB client from QEMU's process-aware ARM target, address process 1 explicitly with `D;1`; an unqualified `D` can return `E22` and leave the VM paused after an otherwise-successful authenticated memory patch.
- Complete each DWC2 endpoint transaction by updating remaining bytes, packet count, and setup count before raising its interrupt; a Guest may reject an otherwise-correct DMA payload when any consumed transfer counter still describes an unreceived packet.
- Publish PMU cable-presence status from an explicit external connection property, and keep the consumed presence bit read-only even when adjacent charger registers remain stored; otherwise Guest writes or a zero-filled reset image can spuriously enter a physical power-off path.
- Bind N82 multitouch from the selected 8C148 DeviceTree and firmware personality: Zephyr2/Z2F52 is on SPI1 with chip select pad 24 pin 0, power pad 7 pin 1, reset pad 6 pin 6, and attention GPIO 155; do not substitute the iPhone 2G Z1 or a later N1 protocol identity.
- In the S5L8900 device-mode USB controller, keep command bits self-clearing and derive `DAINT`, global endpoint status, and IRQ level from endpoint state plus masks; do not migrate duplicate summaries that can disagree with their endpoint owner.
- Treat CPU count as a per-machine hardware contract: iPhone1,2 exposes exactly one ARM1176 core and rejects `-smp 2`; add later iPhone generations as separate machine types instead of widening this board.
- Treat `IOSU ENUMERATE` as host-adapter discovery, not restore evidence. Prove the transport with one combined witness in which pinned `IRecv` requests traverse Guest-programmed endpoint DMA buffers and complete through the same endpoint interrupt path; neither the Host adapter nor a register-only test is sufficient alone.
- Validate an S5L8900 LCD scanout with an actual fixed-size screendump and sentinel pixels across the Guest RAM/alias path; register round-trips alone do not prove window selection, stride, byte order, or color conversion.
- Model a selected raw NAND part with its complete data-plus-spare geometry, and do not reinterpret sparse zero-filled holes as erased `0xff` pages; initialize erased bytes explicitly or use a backing format with explicit allocation semantics.
- Preserve the NAND page buffer and its single authoritative cursor across status polling and FIFO flushes when the Guest transfers main and spare data in consecutive DMA operations; do not restart the page implicitly between those producer-observed phases.
- Keep GPIO edge history separate from level-derived interrupt status: write-one-to-clear removes a latched edge, but must not deassert a level source while its selected input polarity remains active.
- Keep S5L8900 `GPIO_INTSTAT` in the same enable domain as its group IRQ. The 8C148 dispatcher disables a deferred level source before rereading status; returning an active but disabled pin traps the CPU in its interrupt loop and starves the work item that clears the peripheral.
- Decode the S5L8900 timer control register as independent start and manual-update bits, not an enum. The 8C148 event timer writes `3` to load its count and start atomically; rejecting that combined command prevents every kernel callout from reaching the hardware timer.
- Keep the S5L8900 RTC's 12 MHz counter separate from the programmable timer's 24 MHz source and non-linear divider encoding (`4/0/1/2/3` means divide by `1/2/4/16/64`). XNU selects code 1; running that timer at the RTC rate fires deadlines twice early and can starve newly created kernel work.
- Do not conflate the baseband-support PF38F3050 NOR-plus-PSRAM package with the application processor's SST25VF080B SPI boot flash; the latter is 8 Mbit, sits on SPI0 with active-low GPIO pad 4 pin 0 chip select, and the stock 8C148 driver requires JEDEC ID `0xbf258e`.
- Treat the N82 SPI NOR contract as the 1 MiB BF258E device plus two validated 8 KiB Apple CHRP banks at offsets `0xfc000` and `0xfe000`; each bank begins with the 32-byte `nvram` integrity record and must also carry the `common`, `APL,OSXPanic`, and trailing `wwwwwwwwwwww` records.  A generation-valid bank containing only one free record selects successfully but cannot publish writable OF variables through `IONVRAM`.
- Do not reuse a later Samsung UART merely because its register offsets match: S5L8900 `UFSTAT` uses four-bit RX/TX counts at bits 0/4 and full flags at bits 8/9, so keep that generation-specific status encoding behind its own model.
- Keep GID/UID AES fuse identity outside migratable Guest-visible register state: inject each exact 16-byte key through a Host secret, require the destination to supply it independently, and validate the complete DMA interval before reading any Guest data.
- Do not substitute a later Samsung I2C controller for S5L8900: its producer polls the separate W1C operation register at `0x20` for transfer bit 8 and condition-change bit 13, so keep that completion owner distinct from `IICCON` interrupt pending and test it through a real board slave.
- Keep the S5L8900 I2C operation interrupt separate from the classic `IICCON` source: the Apple consumer enables it with bit 0 of register `0x14`, reads register `0x20`, and writes that value back before advancing its transfer state, so W1C must immediately recompute the level even while `IICCON` pending remains set.
- Model each active-low open-drain board interrupt at its producing device and drive the idle high level through the proven DeviceTree pin; do not globally reset unowned GPIO inputs high, because that invents pull-ups for unrelated pads and hides missing endpoint wiring.
- Treat the PCF50635 as an always-on owner across application-processor reset: reset the I2C transaction cursor, but preserve GPMEM and RTC offset; do not guess the N82AP PMU interrupt pin from another S5L8900 product's device tree.
- Treat PCF50635 interrupt status (0x02-0x06) and masks (0x07-0x0b) as separate domains: status is read-to-clear, a mask bit of one suppresses the active-low pin without discarding a latched event, and USB insertion is INT1 USBINS bit 2 while MBCS1 USBPRES remains bit 0.
- Drive PCF50635 USB presence from the configured USB-over-IP transport, not transient socket open/closed events. The Host client reconnects while iBSS and iBEC re-enumerate, but physical VBUS remains present; turning that reconnect into a fresh PMU insertion after status clear traps iBEC in a level-interrupt storm.
- Preserve the WM8991 control protocol as eight-bit register selection followed by complete 16-bit big-endian values: increment only after the low byte, keep invalid indices outside the 0x00..0x3f window instead of mirroring them, and treat codec discovery as distinct from the unimplemented I2S/audio datapath.
- When wiring S5L8900 PL080 peripherals, do not use OpeniBoot's software `DMA_*` endpoint enum as the hardware request input. Close it through the selected controller's peripheral lookup: I2S0 TX/RX are lines 0/1 on either DMAC, while I2S1 TX/RX are lines 2/3 on DMAC1 only; defer a newly asserted request outside the producer's MMIO callback so its FIFO access cannot be rejected as re-entrant I/O.
- For old IMG3 DATA tags, treat the declared logical length and stored tag allocation as separate bounds: AES-CBC consumes the complete 16-byte prefix, while early containers such as the 5A347 DeviceTree retain a clear non-block tail; preserve that tail and trim the extracted artifact to the logical length. Validate both bounds against the enclosing tag and never derive ciphertext padding from the logical length.
- Preserve the S5L8900 SPI controller's TX-then-RX transaction phasing: a variable-length Zephyr2 result request transmits its complete padded command before response clocks begin, so publishing a response at the 16-byte prefix lets the remaining TX words consume and corrupt it.
- Preserve the S5L8900 SPI controller's full-duplex FIFO contract: every transmitted word also enters the RX FIFO and consumes one programmed `TRANSFER_COUNT` word; a zero count leaves transmit-only operation unbounded, while setup bit 0 explicitly enables hardware-generated junk clocks for an RX-only phase. The 5A347 `AppleS5L8900XSPIController` handler reads the prior RX batch, refills TX, and only then acknowledges the old status, so newly produced TX and RX service conditions need independent retrigger ownership and their FIFO data must survive that W1C. An SST25VF080B AAI command accepts exactly two data bytes before ignoring later clocks until chip-select rises. The asynchronous controller can leave `CONTROL` at zero and launch the queued transfer by setting the TX/RX service bits in `SETUP`, so treat either proven start form as active.
- Resolve board-level interrupt wiring through the live producer and consumer, not a serialized ordinal or sibling platform label: both 8C148 iBSS (`0x7040`) and XNU (`0x1150`) consume timer 4 status bit 16 through VIC0 bit 7. Rerouting the one-shot mode to zero-based GPIO input 8 leaves its status pending behind a disabled VIC bit and strands launchd after mounting the filesystems.
- Derive S5L8900X SDIO register offsets from the selected firmware driver's pointer-initialization chain, not a sibling emulator's labels: the 8C148 consumer polls command state at `0x10`, data status at `0x18`, and requires `CMDRDY` to remain set while command-complete is acknowledged separately.
- Model the S5L8900 watchdog's clear and disable keys as commands over one control register, with its count derived from the virtual-clock deadline; the 8C148 driver uses `0x001f4a00` to reload and `0x00100000` for fast reset, so leaving the aperture as RAM suppresses both interrupt and reboot semantics.
- Keep SHA-1 padding in the S5L8900 Guest producer: the accelerator consumes complete 64-byte blocks, preserves the five-word continuation IV behind configuration bit 3, exposes each digest register byte-swapped from that internal state so a little-endian word store produces the standard digest byte string, and treats interrupt completion separately from the polling busy bit.
- Keep the 8C148 ADM firmware boundary generation-specific: action 2 owns the command section, action 3 owns bounded pad data, multi-byte command fields and scatter entries have mixed endianness, and NAND backing remains owned by the FMC device rather than duplicated in the ADM interpreter.
- When ADM firmware actions and a register controller share one NAND backing owner, keep action-side program and erase independent from the controller's page buffer and transfer cursor so asynchronous storage commands cannot corrupt an in-flight register transaction.
- Keep the iPhone1,2 board identity in the SYSIC power-ID word at `0x39a00044`: bits 23:16 are `BDID=4` and are consumed by both the iBSS USB serial producer and IMG3 policy checks, while bits 31:24 retain the independently consumed power epoch.
- Treat the S5L8900 SHA-1 `START` bit as self-clearing at completion. The iBSS producer read-modify-writes the same configuration register to select the continuation IV before loading the next block; retaining `START` therefore compresses the previous block twice.
- Publish one selected N82AP identity coherently: CHIPID `0x3e500008` retains `CPID=0x8900` in bits 31:16 and `SDOM=1` in bits 9:8, while its epoch in bits 6:0 matches SYSIC `0x39a00044` bits 31:24. The unmodified 5A347 chain requires epoch 4 to match iBEC's signed `SEPO` tag, while 8C148 requires epoch 5; a split value stalls iBSS memory initialization, and a coherent but wrong value makes iBSS reject iBEC after parsing it.
- Keep S5L8900 `FMCSTAT` completion domains distinct: bit 1 is command completion, bits 2 and 3 are address and transfer completion, and bits 4 through 11 are per-bank readiness. The iBEC consumer waits and clears command and selected-bank status separately, so command completion must not reuse bank 0's bit or be reasserted by an address transfer.
- When Guest libc writes directly into an MMIO register array, recover its actual access widths and alignment before widening the region contract; merge subword writes into the addressed little-endian lane only for the consumed register window instead of treating a byte store as a whole-register write.
- Do not substitute the public S5L8900 3.0/3.0.1 pseudo-GID for the non-readable production GID fuse.  When only published component keys are available, pair each exact encrypted KBAG with its clear IV/key through an external oracle secret and fail unmatched GID operations instead of silently producing plausible ciphertext with the wrong key.
- When a development VM explicitly provisions a virtual GID fuse for newly generated state, preserve it with that VM's NAND and NOR and keep exact production KBAG oracle records ahead of the virtual-key fallback. Never present the virtual value as Apple's production GID or let it replace an authenticated firmware mapping.
- Keep the S5L8900 EdgeIC distinct from the adjacent PL192 controllers: its two configuration words enable 64 rising-edge latches, its two status words acknowledge pending sources with write-one-to-clear, and N82AP cascades the low and high banks through VIC interrupts 35 and 41.
- Keep S5L8900 AES completion pending until the Guest acknowledges the set bits by writing them back to `AES_STATUS` at offset `0x0c`; the 8C148 interrupt handler uses that W1C operation before returning, so a read-only status register leaves VIC interrupt 39 asserted indefinitely.
- Keep S5L8900 AES completion asynchronous to the `GO` write but available at the next virtual-clock opportunity.  The AppleS5L8900XAES synchronous path polls status only `0x2710` times; a one-microsecond timer can expire that loop under TCG, then consume a later retry's rewritten buffers after the caller has already inspected them.
- Let a read of S5L8900 `AES_STATUS` service an already-deferred AES operation.  Even a one-nanosecond virtual timer can remain undispatched while TCG executes the driver's complete bounded polling loop; poll-assisted completion preserves the required post-`GO` boundary while preventing late DMA from consuming a retry's rewritten sentinel buffer.
- Translate N82AP's MBX child-bus `reg` value `0x03000000` through the `arm-io` range to physical `0x3b000000`, and retain its complete 16 MiB aperture: the AppleMBX driver reads wrapper status at `+0x12c` but also writes command memory at `+0xa00000`, so a register-page-only model is structurally incomplete.
- At the 8C148 CalmADMFMC firmware-start boundary, publish all eight little-endian per-chip-enable device-ID slots in event action 3 before completion: populated banks carry the NAND owner's ID and absent banks are zero. A ready mask or correct controller FIFO reads do not initialize this separate firmware-owned result array.
- Accept CalmADMFMC opcode `0x100` only as its observed zero-page, zero-pad initialization record and publish a zero result before the event interrupt; it is a distinct firmware lifecycle command, not a malformed NAND transfer.
- When a Guest driver sleeps on a hardware completion flag, do not assert the completion interrupt synchronously inside its start-register write: preserve a nonzero asynchronous boundary so the interrupt cannot clear and wake the condition between the caller's last predicate read and its actual sleep.
- When a higher-level peripheral transaction consumes a PL080 payload, traverse the Guest's LLI chain through the next descriptor that requests terminal count, preserve the loaded next descriptor, and publish each terminal-count boundary separately; clearing the LLI or retiring the whole chain loses the driver's software-ring reconciliation state.
- Do not advance a linked PL080 peripheral transfer while its prior raw terminal-count bit remains set.  A level interrupt can coalesce repeated completions, so require the Guest's write-one-to-clear acknowledgement before consuming the next segment.
- Keep an exact erased NAND baseline immutable and run every mutable boot from a writable copy-on-write clone. Restore user-write permission on the clone when the immutable source is read-only. Reset contamination at the physical data-plus-spare page geometry across the complete image; restoring only the first visible page cannot repair writes elsewhere in a multi-bank backing.
- Keep USB-over-IP discovery reads bounded until enumeration succeeds, then switch the established socket to blocking bulk/control service.  Otherwise a stale first connection after Guest re-enumeration can make a pinned `IRecv(timeout=...)` wait forever before its own retry loop can run.
- After USB-over-IP enumeration switches the socket's default to blocking, still apply each control or bulk request's supplied timeout while awaiting its response; a Guest reset can discard a pending endpoint transaction without closing the Host socket.
- Do not classify an iPhone3G black Cocoa frame as a GPU failure until the LCD power sequence and MBX result traces are paired: iOS can remove the active window, write `LCD_DISABLE`, and clear `VIDCON0` after a valid Metal-rendered lock screen, while a later modeled Home press republishes that screen without any decoder rejection.
- Close a framed USB-over-IP connection after any request timeout.  Its eventual late response retains the old request ID and would otherwise be consumed as the next request's header, corrupting stream synchronization.
- For a single-client USB-over-IP backend, weakly track the adapter's discovered device, close any surviving handle before rediscovery, and give the device one idempotent socket finalizer.  A client constructor can fail after discovery without disposing resources, while strong adapter ownership would prevent a successful context that only drops its reference from releasing the socket.
- Do not infer symmetric DMA ordering from a shared peripheral request number: the 8C148 ADM consumer requires memory-to-peripheral write completion before `RUN`, while peripheral-to-memory read completion follows the action that produces its payload.
- Treat ADM `RUN` as the authoritative write-record commit boundary: an earlier memory-to-peripheral terminal count can observe a syntactically valid stale shared record, so never freeze it before `RUN`; once `RUN` commits a write-shaped record, keep it pending across arbitrary Host scheduling delays until the producer's final acknowledged terminal count instead of converting a late PL080 registration into a successful lifecycle-only event.
- Once a late PL080 memory-to-peripheral transfer starts for a pending ADM `RUN`, its terminal count owns the transition. An older arm-grace timer may still fire while DMA is active and must not publish or clear that transaction.
- Bind every deferred ADM write completion to the immutable transaction validated at `RUN` or its post-`RUN` final terminal count, including payload, targets, and command class. The Guest can rewrite the shared action record during the one-microsecond notification delay, so the timer may commit the snapshot and publish the event but must never classify or parse the live record again.
- For S5L8900 AES, keep the logical transfer length at register `0x18` separate from the current scatter/output (`0x20`/`0x24`) and gather/input (`0x28`/`0x2c`) segment address/capacity pairs. Read input from `0x28` and write output to `0x20`; the official recovery SHSH producer proves this with distinct buffers, while in-place firmware decrypts cannot prove direction. Status bit 2 asks the gather feeder for the next input segment and bit 1 asks the scatter feeder for the next output segment; they are not generic error bits. Preserve CBC state across both refill paths.
- Bound S5L8900 AES DMA by the selected board RAM contract rather than an invented 16 MiB command ceiling: 5A347 iBEC decrypts the restore ramdisk in one in-place `0x01810000`-byte operation at `0x0c000020`, with every consumed capacity field matching that span.
- Preserve S5L8900 AES partial-block behavior at the IMG3 boundary: 5A347 iBEC can publish the raw DATA logical length (such as `0x9b5c`), while the engine consumes only complete 16-byte blocks and leaves the trailing bytes untouched; OpeniBoot expresses the same contract by rounding down before submission.
- Select the GID KBAG oracle with the firmware profile, not merely the shared board hardware: 5A347 and 8C148 wrap different per-component IV/key material, and an all-zero fallback fuse can complete AES while silently producing unusable ramdisk, DeviceTree, and kernel plaintext.
- Give each development VM one persistent randomly generated UID-key secret and preserve it with the NAND across boots and erasures; 5A347 iBEC encrypts `iBootSleepValid` through the UID domain, so omitting the key stalls boot while changing it invents a new virtual device identity.
- Open the development UART file through an append-enabled chardev so a restart or migration-recovery attempt cannot truncate the prior boot evidence; the boot helper already records its starting offset and therefore consumes only the current attempt.
- Patch iBEC boot arguments only after iBEC has staged the DeviceTree, ramdisk, and kernel, and authenticate the original 40-byte buffer before writing it; the same physical address is zero/unowned during iBSS and an early write corrupts the later handoff.
- Preserve the 8C148 recovery request asymmetry: iBSS executes `go` through vendor request 1, while iBEC executes `bootx` through vendor request 0; request 1 at the latter boundary resets back into iBSS instead of entering the kernel.
- Treat every iPhone OS 2 DFU-compatible file terminator as a USB reset boundary: dispose the old Host connection, reconnect to the same boot stage, and only then submit that file's `go`, `ramdisk`, `devicetree`, or `bootx` command; its iBSS `go` uses vendor request 0 rather than 8C148's request 1, and its first iBEC re-enumeration needs a 120-second Host budget under single-threaded TCG. Reusing the pre-reset socket times out, while omitting `go` leaves iBSS active and makes a later ramdisk upload overwrite the staged iBEC.
- Keep the S5L8900 AES status owner separate from its interrupt publication mask: register `0x10` gates status bits 0 through 2 onto VIC39. A synchronous request sets this mask to zero and polls status directly, so asserting the line from raw status alone schedules a stale work-loop callback after its active request is already retired.
- Preserve N82AP's `tv-out` register vector in serialized index order: indices 0, 1, and 2 translate to physical `0x39300000`, `0x39200000`, and `0x39100000`. AppleH1DisplayDrivers maps each index independently and writes its lookup table through index 2; none of these apertures is an alias or relocation of the panel LCD at `0x38900000`.
- Decode S5L8900 LCD format 7 as the 8C148 driver's 32-bit ARGB8888 scanout. Its active 320-pixel window publishes a 1,280-byte stride; rejecting that format blanks a correctly configured AppleH1CLCD service even when the framebuffer address and geometry are valid.
- Publish a black 320x480 surface when the S5L8900 LCD is realized, reset, restored disabled, or has no valid scanout. Leaving the Cocoa surface untouched exposes the frontend's white allocation as a false Guest display state before iBEC or XNU enables the panel.
- Keep AppleH1CLCD frame completion in its shared interrupt domain: register `0x14` masks status, register `0x18` latches frame bit 0 and clears written bits, and the IRQ level is their intersection. The swap producer clears stale bit 0 before enabling it, while the interrupt consumer acknowledges bit 0 before retiring the queued surface; an unrelated always-high line cannot wake a later empty-to-nonempty transition.
- Preserve AppleH1CLCD window priority and premultiplied ARGB composition when several full-panel surfaces are enabled: higher-numbered windows blend over lower-numbered windows. The 8C148 restore UI leaves its Apple logo in window 1 and publishes a transparent progress overlay through window 3, so selecting either single window loses part of the live screen.
- Do not use `DIRTY_MEMORY_VGA` to track composited AppleH1CLCD surfaces inside the board's shared system-RAM `MemoryRegion`: its logging scope instruments every Guest RAM write and can cut single-threaded TCG restore throughput by roughly two thirds. Keep a bounded Host shadow per active surface, compare logical rows, and recomposite each changed row from all active layers.
- Keep PCF50635 ADC results owned by the selected `ADCC1` mux. N82's `function-read_acc` consumes the ADCIN1 result byte's high nibble as the 30-pin resistor ID: `0xa` selects `USBHostAltConfig`, while the open-circuit `0xf` is normalized to no accessory. Reusing the battery sample across muxes therefore changes the Guest's USB personality.
- Treat a Host-requested USB reset as a bus event over the live device controller: clear the USB address/configuration view and raise reset/enumeration interrupts, but preserve the Guest-programmed DWC registers. A QEMU device cold reset destroys the endpoint state needed to handle the next setup packet.
- Preserve a Host bulk-OUT zero-length packet as a real Guest endpoint transaction. Upstream usbmuxd appends that ZLP when a write ends on the 512-byte high-speed packet boundary; acknowledging it before the Guest arms and completes its endpoint loses the transfer delimiter.
- Reject a second long-lived iPhone boot before rotating logs or starting its upload helper. The QEMU pidfile is the instance owner; checking it after those side effects can erase current evidence and let a failed duplicate launch occupy the single-client USB transport.
- Once a persistent activation record has been validated through an unpatched cold boot, keep the ordinary development target on that path. A global raw-address breakpoint for transient userspace patching is a diagnostic fallback: leaving it armed during every boot can stop unrelated launchd children that map the same virtual address and distort startup timing.
- Treat the Zephyr2 eight-frame queue as a bounded backlog, not a limit on total gesture samples. Pace a smooth Host-injected swipe so the Guest drains frames concurrently, retain the terminal release when the backlog fills, and verify the live start/move/release sequence at the real SPI consumer before shortening it for convenience.
- When an ADM command overlays its page count with an in-place completion result, derive a late-armed read DMA from the opcode plus that result boundary. The same arm command precedes a write but follows a read, so neither a fixed direction nor a duplicate phase flag represents the wire protocol.
- Decode CalmADMFMC targets from their opcode-selected layout: opcodes `0x200`/`0x400` publish one seed per chip enable and expand page `i` by cycling those seeds and adding `i / ce_count`, while `0x300`/`0x500` publish one explicit bank/page pair per page. Never consume the untouched compact-layout tail as explicit targets.
- Treat each CalmADMFMC data descriptor length as available capacity, not an exact transfer total. Bound every copied byte by that capacity, then validate the complete zero-terminated vector: the final used descriptor can retain space and valid unused descriptors can precede the terminator, because the 8C148 ASR verifier emits a 128-page request whose vector has an 8 KiB merged entry plus one unused trailing 4 KiB entry.
- Keep each iPhone1,2 firmware era behind an authenticated profile instead of reusing 8C148 addresses and manifest keys: 5A347 predates `BuildManifest.plist`, names its kernel through `RestoreKernelCaches`, links iBSS at `0x22000000` rather than `0x18000000`, and stores the exact iBEC restore boot-argument buffer at `0x18016b30` rather than `0x18020634`.
- Select the iPhone OS 2 upload protocol from the firmware-generation identity, not recovery PID or interface descriptors: libirecovery treats CPID `0x8900` recovery without ECID/`IBFL` as DFU-compatible. Keep iBSS at its 2 KiB `DNLOAD` size, while 5A347 iBEC can safely coalesce to its observed 8 KiB destination stride; a larger control request can report its full Host length while silently retaining only 8 KiB. Preserve suffix/CRC, zero terminator, and USB reset in both stages.
- After a delivered iPhone OS 2 iBEC stage command times out in the control status phase, issue one Host USB bus reset and reconnect before the next file; do not reset the application processor or resend the command. The handler has already committed the ramdisk/DeviceTree state, but the expired framed connection otherwise leaves the next configured-client handshake unreachable.
- Once an authenticated firmware profile has retained every extracted boot artifact and external key oracle, let ordinary prepare and boot targets consume those retained artifacts without reopening the source IPSW; require the archive again only when extraction is incomplete.
- Treat absent legacy lockdown identity values as absent plist keys, not null values or invented identities. When usbmuxd keys a record by an old descriptive iBoot serial, accept the complete separator-free serial as one safe path component rather than assuming a hexadecimal UDID.
- Let pymobiledevice3's canonical autopair path own the legacy lockdown sequence: it validates an existing record or pairs, then validates again and starts a session. A successful `Pair` request alone does not authorize Diagnostics, and duplicating that state machine around `autopair=False` can return a client with no `SessionID`.
- Keep Guest halt and Legacy FTL commit as separate shutdown domains. Diagnostics Shutdown can reach `reboot(RB_HALT)` and USB PHY power-down while the newest FTL record remains the dirty `0x4f` marker; on iOS 4, Diagnostics Sleep commits the child metadata and final clean `0x43` root. For a Host-managed poweroff, require a fresh successful root write after the Sleep request, then stop the authenticated QEMU owner before the unmodeled deep-sleep path continues.
- Bind a ready-state migration stream to exact immutable clones of its NAND, NOR, and fuse secrets while the source remains paused in `postmigrate`; resume only from a fresh disposable clone of that complete set. Reusing VM state with a backing changed by a prior resume silently splits the in-memory FTL view from persistent flash and is not a startup optimization.
- Resume the source VM after an external ready-state checkpoint is durably published; snapshot creation is a development aid, not ownership transfer, and a bad restore must not discard the already-warm interactive session.
- Keep the live-proven software MBX backend as the ordinary playable target. A narrow Metal offload remains an explicit experiment until the same wake, first-presentation, and post-lock interaction sequence is at least as reliable; backend realization and accepted submissions alone do not establish display usability.
- Throttle Host-side progress redraws for high-frequency recovery transfers: an unbounded terminal stream can fill the PTY and reduce an otherwise 40-packet/s iPhone OS 2 DFU upload to roughly 5 packets/s. Keep byte/packet accounting exact while limiting display refresh frequency.
- For the pinned pymobiledevice3 iPhone OS 2 DFU-compatible upload, let each synchronous `DNLOAD` control transfer establish its own completion with a bounded timeout long enough for single-threaded TCG.  If one indexed block times out, close the desynchronized framed connection, re-enumerate the live iBEC, and retry that same block before advancing; then wait for state 5 once after the complete image before the zero terminator and two final status reads. A redundant `GETSTATUS` after every 2 KiB block returns iBEC to its UART-polling main loop and turns a 12,322-block ramdisk upload into an hour-scale TCG run.
- Admit all 512 CalmADMFMC data descriptors consumed by a maximum-size 512-page command, then validate the separate zero-length terminator at index 512. Do not reserve that terminator by reducing the usable descriptor count; restored's ASR verification emits one 4 KiB segment per page across the full command.
- When a transaction backend has already consumed its storage I/O synchronously, treat its completion timer as an ordering boundary rather than an invented media latency. Keep it nonzero but below the Guest scheduler's quantization, and validate the choice against a live repeated producer loop; a nominally small delay can otherwise expand each command into a full scheduling interval.
- When validating a restored FTL image, do not classify a present but nonmatching logical page as a corrupt current write until every physical version is inspected. An older all-erased mapping with a valid USN and spare record can survive when the later transaction was skipped, making the current payload absent rather than mutated.
- Treat IOSU enumeration, restored port 62078 readiness, and NAND readiness as separate boundaries: bounded-retry the service open and `QueryType` as soon as the unique device appears, including early connection refusals, but defer the single `StartRestore` until the current boot reaches `FTL_Open [OK]`. Submitting during `recover` can miss the storage-ready wakeup and retain restore ownership after the Host disconnects, while waiting for storage before opening the service can let the legacy request loop time out.
- Complete an enabled zero-length bulk-IN endpoint as the Guest's short-packet terminator. A restored/usbmux message can end on the 512-byte high-speed boundary; ignoring its following device-to-Host ZLP leaves the Host read pending and blocks the Guest before its next progress message.
- Preserve each 5A347 AppleImage3NORAccess external-method input as one bounded IMG3 transaction.  The consumer rejects sizes at or below 0x400 or at or above 0x80000 and requires the IMG3 declared full size, rounded to 64 bytes, to equal the rounded call size; capture each producer call boundary before blaming total NOR capacity or bypassing the real program result.
- Do not interpret a reverse-engineered integrity helper's zero result by convention alone; close it through the immediately consumed condition and terminal error path.  Patch only the authenticated failure branch so the real downstream storage result remains authoritative.  When one Host payload drives repeated calls through that check, keep one restore owner across the complete batch; at the Host terminal boundary, stop the Guest, authenticate the replacement bytes again, restore and read back every original instruction, and only then detach.
- A userspace virtual breakpoint can fire in a forked or exec'd child at the same address while the patch owner waits on external tools.  Accept a completion only when the complete authenticated instruction window containing that PC matches the active owner mapping; temporarily remove the breakpoint, single-step the colliding instruction, and reinstall it before resuming, because continuing with the breakpoint armed retriggers at the same PC.
- When one restore payload drives a batch of encrypted IMG3 writes, bind every production KBAG in that batch to its exact published clear IV/key.  A virtual random GID can make an unmatched AES operation return successfully while producing a wrong image key, so successful accelerator completion is not evidence that a later flash writer received valid plaintext.
- Do not treat completion or timeout of a 5A347 iBEC stage-command control request as proof that its asynchronous command ran. Before overwriting the shared upload buffer, authenticate the exact producer and consumer instruction windows and require the DeviceTree address/size state to be stably published; retry only the idempotent command when that state remains absent.
- At the 5A347 iBEC DeviceTree publication boundary, keep the USB transport and GDB observation endpoints distinct, and compare the producer state against physical destination `0x0bf00000` plus the IMG3 DATA tag's logical length; neither the kernel virtual mapping nor the complete container size represents that state.
- Keep a Guest bulk-IN endpoint active when one Host read consumes only a packet-aligned prefix of its declared transfer. Advance the endpoint DMA address and remaining byte/packet counts without raising transfer-complete; otherwise a 16 KiB Host read can retire a 32,764-byte usbmux frame early and splice the following frame into its tail.
- Preserve S5L8900 FIL's erased-page result through CalmADMFMC: completion overlays command/media halfwords at command offset `0x28`, and also publishes command, media/ECC, per-read, and reserved halfwords through the low 16 bits of `EVENT_DATA[0..3]`. The shipped ADM driver copies those four event words into the FMC result object before acknowledging command 4, so changing shared RAM alone is invisible to its parser. An all-`0xff` main area with at most one programmed spare byte returns command/media status 0 and per-read result `0xfe`; AppleS5L8900XADMFMC maps that marker to `0xe00002e5`, and the NAND wrapper converts that exact code to raw return 1 so `_LoadFTLCxt` continues its backward scan. Do not classify from spare alone because raw device metadata can have programmed main data with an erased spare.
- Protocol 11 does not persist the Host's nested `SystemImage=false` into 5A347 restored's local options plist.  To resume a verified filesystem, authenticate the partition and `restore_images` decision/return windows in one transaction, transiently select both existing zero-result paths, and restore every instruction before the consumer checks and mounts both volumes for `fixup_var` and NVRAM.
- When Host USB discovery starts before the Guest can answer endpoint-zero requests, retry the explicit bus reset on a bounded cadence while descriptor reads fail. One reset issued before the Guest stack is ready followed by control-only retries can consume restored's complete event deadline even though a fresh connection would enumerate immediately.
- Select restored readiness and identity queries by the negotiated restore protocol generation: protocol 11 does not implement the `HardwareInfo` value query, while both protocol 11 and protocol 12 must defer `StartRestore` until `FTL_Open [OK]`.
- Complete CalmADMFMC peripheral-to-memory DMA for both per-read result 0 (data) and `0xfe` (erased page), retain the arm while its PL080 request channel is not yet enabled, and re-evaluate that readiness after the channel appears. The 5A347 producer consumes the all-`0xff` payload even when FIL separately reports the page empty, and can arm ADM before programming channel 5; suppressing that DMA or checking availability once leaves the Guest asleep without terminal count.
- After an interrupted legacy protocol 11 restore has proved that both filesystem partitions were formatted, do not trust `CreateFilesystemPartitions=false` alone: a live 5A347 request still entered the wipe path even though the final consumer decompiles to honor false. Authenticate that consumer's decision and epilogue windows, transiently set its return register to zero and branch to its own epilogue, then restore/read back both instructions before restore proceeds.
- Keep the ASR data connection alive after the Host has only queued the complete system-image payload, then close it at the first authenticated downstream completion boundary. For legacy 5A347 that boundary is the post-copy checksum/repair epilogue: closing earlier can interrupt slow Guest consumption, while retaining the stream beyond that epilogue withholds the EOF ASR needs to finish and eventually reports `Operation timed out` after a successful 100% verify.
- Give every disposable run artifact an explicit cleanup boundary and remove it as soon as its evidence has been retained. Never leave completed or failed runs in `/private/tmp`; move the single successful reusable disk into an ignored project artifact directory, and delete failed full-size NAND images before starting another attempt.
- A legacy ASR checksum bypass must remain downstream of the complete image write and readback: authenticate the checksum, volume-resize return, and cleanup windows, bypass only the rejected checksum and observed resize error returns, preserve the following HFS volume-header repair chain, then restore/read back every original branch at the cleanup epilogue. Jumping directly from the checksum to that epilogue leaves the copied volume unfinalized and makes restored's following `fsck_hfs` wait indefinitely.
- Attribute a legacy ASR post-copy timeout at the actual optional return sites: trap each reached site, retain its `R0` and `LR`, and distinguish an operation that returned an error from later code that merely reports the shared cleanup result. A terminal error string or the cleanup PC alone cannot identify which volume-header step failed.
- QEMU's ARM gdbstub pauses the running VM when this minimal client connects, so establish the initial stopped state with `?` before inserting a breakpoint; sending an additional raw interrupt while already paused waits for a second stop reply and deadlocks the Host helper before payload transfer.
- End a transient GDB patch transaction with the stub's detach command while the CPU is stopped; resuming and then closing the socket can leave a delayed stop reply for the next debugger and make its first breakpoint command consume a stale `T05` packet.
- On a dedicated freshly reset 5A347 emulator NAND, skip only restored's security-wipe call, not its partition-creation function: authenticate the call site, return zero in place of the 500 MiB all-`0xff` pass, then preserve IOMedia remount and both `newfs_hfs` calls before restoring the original instruction at the function epilogue.
- When a post-copy HFS repair returns `-123`, distinguish media I/O failure from ASR's synthetic bad-signature result inside the volume-header reader: authenticate and observe the sector-2 read return, the primary and embedded signatures, any wrapper-sector read, and the final sector write. The shared outer return cannot identify which of those paths produced the same numeric result.
- Do not treat a legacy ASR `Verified block checksum` progress line as a checksum match when the following compare is transiently bypassed. Capture the computed and expected values at the compare itself and retain a bounded raw sector-2 sample before its endian conversion; a successful media-read return plus a bad HFS signature proves only that bytes arrived, not that the copied image matched its source.
- Do not treat a deleted macOS temporary path as proof that its disk image is released. Inspect `hdiutil info`, detach every matching device node, and only then remove the backing path; an unlinked image can remain mounted after its directory disappears.
- To attribute post-copy filesystem-header corruption, capture the same raw target sector immediately before and after the first mutating repair call. A valid checksum before that boundary and a bad signature only after it identifies the repair path; either observation alone still conflates the image writer with post-processing.
- Preflight every bank/page target in one CalmADMFMC command before programming its first NAND page. A late invalid target otherwise leaves a committed prefix; the Guest retries the failed command and programs those uncleared pages again, so NAND's one-to-zero semantics turn a recoverable descriptor race into persistent data corruption.
- Do not freeze a legacy restore NAND from same-boot ASR verification or filesystem checks alone. Require restored's terminal success followed by a cold-boot filesystem check, because failing later during NOR flashing can leave the live FTL view valid while the persisted checkpoint selects an invalid logical version after reset.
- Preserve the AArch32 secure-state bit when converting ARM coprocessor migration indexes back into internal register keys. KVM's decoder intentionally forces AArch32 indexes into the non-secure bank, but QEMU's migration list also carries synthetic secure entries in that otherwise KVM-shaped encoding; using the KVM conversion for vmstate silently saves and restores the wrong SCTLR, TTBR, and DACR bank on an ARM1176 with EL3.
- Freeze a live VM before starting an outgoing ready-state migration when the checkpoint is meant to capture an exact visible or interaction boundary. Pre-copy migration lets the Guest advance until switchover; even a few seconds can turn an authenticated visible frame into a later auto-locked state while the Host still labels the artifact from the earlier observation.
- Treat a frozen ready-state migration as paused state at both ends: explicitly continue the incoming VM after its stream is loaded, and make companion input/display controls discover the disposable resume directory instead of silently targeting the persistent cold-boot directory.
